`npm run db:data` in `back/` empties a development database and fills it with demo data for the
whole system: staff roles and logins, three venues with courts, hours, rates and closures, two
weeks of past games, bookings past and upcoming, and their cash and online payments. No video is
seeded.

## Dev notes

- back/: `scripts/seed-demo-data.js`. It truncates every table except `_migrations` and
  `permissions`, and keeps only the Owner role, its permissions and the Owner account (login and
  sessions). Then it seeds the demo, so every run starts fresh. Video files on disk aren't deleted.
  It refuses to run with `NODE_ENV=production`.
- Demo logins share `DEMO_PASSWORD`, or a random password printed once.
- Seeded games are already settled and there are no recorder boxes, so the API's jobs leave the
  demo alone: no video rows, no alerts, no emails. Upcoming bookings are marked as already
  reminded.
